# Стратегия сидушек: 100 ₽ и цена конкурента −10 ₽

Согласовано 13 октября 2026: стартовая цель и нижний предел прибыли 100 ₽/шт.;
следующие ступени по 10 ₽ при стабильных заказах; любое снижение вслед за конкурентом
требует отдельного решения владельца. Старая цель покупателя 220–240 ₽ удалена из решений Ozon.

## Что реализовано

- `config/bath-pricing.json` — серверный источник правил и настроек четырёх Ozon SKU.
- `lib/bath-pricing.js` — чистый расчёт, проверка источников и кандидата для всех четырёх действий.
- Сопоставляется минимум выбранных конкурентов, а не неподтверждённый диапазон 250–300 ₽.
  При 250 ₽ целевой ориентир 240 ₽, при 300 ₽ — 290 ₽.
- Одна и та же единица товара, регион, способ оплаты, публичные скидки и доставка должны
  соответствовать одному `contextKey`. Индивидуальные купоны нельзя незаметно смешивать с ценой по Ozon Карте.
- Наблюдения действительны 24 часа; отсутствие любой выбранной карточки блокирует решение,
  чтобы исчезновение дешёвого конкурента из выборки не вызвало ложного повышения.
- Все снижения возвращают `HOLD` и предложение с ценой, прогнозом прибыли и вопросом владельцу.
  Предложения ниже текущей ступени прибыли блокируются. Разрешения на прибыль ниже 100 ₽ нет.
- Прогноз для промо использует цену кандидата только после подтверждения связи с выплатой продавцу.
- Fallback расходов 120 ₽ и расходы другой сидушки годятся только для предварительной оценки.
  Нули не подменяются значением 120. Неизвестная комиссия или эквайринг блокируют изменение.
- Dry-run, проверка `executable` и проверки перед записью сохраняются. Автоматическое удаление
  товаров из бустинга удалено из ежедневного цикла как обход общей политики.
- Стартовый минимум единого отчёта, включая WB/ЯМ, теперь 100 ₽. Конкурентная стратегия и ступени
  в этом изменении подключены только к Ozon. WB/ЯМ остаются в прежнем dry-run без записи.

## Период наблюдения: рабочие значения для dry-run

7 полных дней после начала ступени сравниваются с предыдущими 7 днями. Нужны обе полные
недели без пропусков и дублей, минимум по 21 заказу в каждом окне; допустимое снижение
заказов — не более 10%. Это первоначальные параметры, не подтверждённая статистическая модель спроса.
Объём отзывов не используется как доказательство текущей стабильности заказов.

При выполнении условий предлагается ровно одна следующая цель `targetProfit + 10`.
Дополнительно проверяется, помещается ли новая защитная цена в рыночную цель, лимит шага 5%
и лимиты акции. Повторный dry-run не наращивает цель ещё раз.
`stageStartedAt` пока `null`: прошедшие дни старой стратегии не считаются наблюдением новой.
Начало периода и новая цель должны сохраняться атомарно после фактического применения ступени,
а не по числу запусков cron. Исполнитель переходов и постоянное хранилище ещё не подключены.

## Что пока НЕ запущено

1. **Мониторинг конкурентов.** Выбран один конкурент 5459795463: серая EVA-сидушка 40×25 см.
   Он сопоставлен только с собственной серой сидушкой productId 2808600941 (offerId 30092025),
   название которой проверено через `seller-products`. Остальные цвета не приравниваются автоматически.
   В `competitorCatalog` сохранён исходный скриншотный ориентир: 255 ₽ с банками акции,
   280 ₽ с другими банками; целевой ориентир по снимку 245 ₽. Регион и полный состав банков
   неизвестны. `liveEligible:false`: этот снимок не входит в свежие наблюдения и не разрешает изменения.
   Автоматический источник конечной банковской цены не подключён. В существующем расширении
   `pickCurrentPrice()` берёт первое число и не доказывает цену со всеми скидками.
2. **Поток наблюдений.** Файл наблюдений — входной контракт для тестов/проверенных снимков,
   не сборщик. Требуется источник текущей цены выбранных карточек и собственной карточки
   при одинаковых условиях. После выбора карточек нужно проверить доступность такого источника.
   Снижение цены можно обнаружить; причину «максимальный бустинг» нельзя утверждать без отдельного подтверждения.
3. **Фактическая экономика.** `bath-finance.js` выдаёт агрегаты по начислениям, не подтверждённую
   полную прибыль на единицу. Пока `unitEconomicsVerified` отсутствует, исполнение запрещено.
   Перед его установкой нужны сверка количества, повторных начислений, возвратов, расходов без SKU,
   схемы FBO/FBS, налогов и дополнительных затрат. Унаследованные 55 ₽ себестоимости и 0 ₽ допрасходов
   не являются новой проверкой затрат. Промосвязь требует отдельной сверки.
4. **Подтверждение снижения.** Текст вопроса включён в существующий ежедневный отчёт;
   обработчик ответа/кнопок ещё не подключён. Ответ не выполняет операцию автоматически.
   Будущий допуск должен привязываться к товару, действию, точной цене, снимку рынка, версии правил
   и сроку действия. После смены цены конкурента или расходов нужно новое подтверждение.
5. **Live.** Ни одно решение не получает `executable:true`. Одного переключения dry-run-флага недостаточно.
   Цены и акции данным изменением не переключаются. Без данных ожидаемый результат — HOLD.

## Контракт наблюдений (пример структуры, не реальные данные)

Для каждого собственного productId в `products`:

```json
{
  "own": {
    "price": 240,
    "verified": true,
    "finalBuyerPrice": true,
    "inStock": true,
    "source": "идентификатор проверенного источника",
    "contextKey": "регион|оплата|единица товара|скидки",
    "observedAt": "ISO timestamp"
  },
  "competitors": {"выбранный-id": "объект с теми же полями"},
  "promoSettlementVerified": false
}
```

`verified` — результат проверки источника, не переключатель для обхода блокировки.
Наблюдения и подтверждения нельзя принимать из неавторизованной публичной формы.

## Интерфейс и проверка

`GET /api/bath-policy` показывает серверную стратегию только для чтения. Существующие поля
калькулятора явно названы локальным сценарием; они не являются изменениями серверных настроек
или разрешением снизить цену. Миграция `ozonSellerCostsV1 → V2` сохраняет заметки о затратах,
но не переносит старые дефолты прибыли 150/200 как разрешение новой стратегии.

`npm test` запускает чистые и интеграционные тесты без запросов в Ozon или Telegram.
Проверяются пороги, промоцены, конкуренты, свежесть, ступени и полный dry-run с включёнными
в тесте флагами автоцены. Реальные начисления и поведение скидок проверяются отдельно после подключения данных.
